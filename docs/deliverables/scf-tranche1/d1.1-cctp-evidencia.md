# D1.1 — CCTP en vivo: USDC de Base Sepolia al vault, demostrado on-chain

**Entregable (SCF #45, Tranche 1):** *"a testnet transaction bridging USDC via
CCTP into the vault, plus the PR in the public repo."*
**Corrida:** 2026-10-12 · **PR del código:** [#5](https://github.com/LuchoLeonel/lendoor-stellar/pull/5) (+ review en `docs/reviews/pr5-cctp-executor.md`)

## La corrida, paso a paso

1 USDC quemado en Base Sepolia llegó al vault de Stellar testnet como shares
del beneficiary, en **modo vault**: el hook del mensaje CCTP apunta al relayer
y el executor deposita vía `deposit_from` acreditando las shares al usuario.

## Reproducir

```bash
# env: EVM_PRIVATE_KEY, STELLAR_RELAYER_SECRET, CCTP_BENEFICIARY,
#      CCTP_MODE=vault, CCTP_VAULT_ID, CCTP_AMOUNT_USDC (ver cctp-demo.ts)
cd backend
yarn cctp:demo trustline        # una vez: trustline USDC del relayer
yarn cctp:demo burn             # approve + depositForBurnWithHook en Base Sepolia
yarn cctp:demo deliver <burnTx> # Iris → mint_and_forward → deposit_from
```

## Notas honestas

- **Source chain:** el brief de la submission dice "bridge USDC from Celo";
  CCTP **no soporta Celo** como dominio (verificado contra la config oficial
  de Circle). La medida de completitud no fija chain de origen; el demo usa
  **Base Sepolia** (dominio 6). Si Circle habilita Celo, el mismo código corre
  cambiando la config de chain (`cctp-chains.ts`).
- **Standard Transfer** (finality 2000, `maxFee 0`): sin fee on-chain de
  Circle; la attestation tarda minutos. Fast (1000) exigiría `maxFee > 0`.
- Gotcha operativo: tras el `approve`, el `estimateGas` del burn puede ver
  estado viejo en el RPC público balanceado ("transfer amount exceeds
  allowance") — reintentar alcanza.
- 🔴 Testnet de Stellar se resetea el **2026-12-16**: estos contratos y txs
  mueren con el reset; los links de Basescan sobreviven.
