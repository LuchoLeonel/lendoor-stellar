## La corrida, paso a paso

wallet Stellar embebida en el primer login, se autenticó contra el backend vivo

Soroban reales en testnet** desde la UI, cerrando en un depósito al vault — el

## Reproducir

```bash
# frontend/.env (local): VITE_CHAIN_MODE=stellar · VITE_PRIVY_APP_ID=<app id>
#   VITE_FREIGHTER_DISABLED=true          # fuerza el camino sin extensión
#   VITE_SOROBAN_VAULT/VITE_STELLAR_VAULT_CONTRACT_ID=CCXUEBC3… (Instaward)
#   VITE_SOROBAN_USDC=CBIELTK6… (USDC de Circle)
#   VITE_PUBLIC_BACKEND_URL=http://localhost:5173/__api
cd frontend
DEV_API_PROXY_TARGET=https://stellar.api.lendoor.xyz yarn dev --port 5173
# → /borrow: "Continue with email" (Privy) → login → wallet embebida
# → fondear (friendbot + USDC testnet con trustline) → /lend → Deposit USDC
```

## Notas honestas

- **El bug que hacía imposible este flujo** estaba en main hasta PR #7: el
  nonce de auth se firmaba SIEMPRE con Freighter; un usuario Privy sin
  extensión nunca obtenía token. El fix enruta la firma por el registro de
  firmantes (mismo patrón adapter que ya usaban las transacciones).
- **Frontend dev local contra el backend vivo** (`stellar.api.lendoor.xyz`)
  vía el proxy `/__api` de vite: el CORS de prod bloquea localhost — no es un
  gap, es la config de prod haciendo su trabajo.
- **Par de contratos:** el deployment canónico de stellar.lendoor.xyz usa el
  SAC **nativo** como "USDC" de testnet; este demo corre contra el vault
  Instaward + USDC real de Circle (misma interfaz de contrato) para que la
  historia cierre con D1.1: el USDC que entró por CCTP es el que el usuario
  deposita.
- **El wizard de borrow no es parte de la medida de D1.2** (el borrow ya fue
  demostrado por Lucho). En esta corrida igual se ejercitó: términos ✓, email
  OTP ✓ (con alias de Gmail — el email del tester ya estaba registrado con la
  wallet vieja de pruebas); el paso de teléfono quedó bloqueado por el mismo
  motivo (`409 Este número ya está registrado con otra cuenta`) — es data de
  pruebas previa en el backend vivo, no un gap del producto; se libera con un
  `UPDATE users SET phone = NULL …` sobre la cuenta vieja.
- 🔴 Testnet de Stellar se resetea el **2026-12-16**: contratos y txs mueren
  con el reset.
