# D2.1 — Privy wired end-to-end into the credit flow: evidence (testnet) — IN PROGRESS

Measure of completion (award text): *an end-to-end testnet run: onboard via Privy, borrow, repay,
score update.* Pair **T2-A** (Circle testnet USDC): vault `CA23BR7WLIPAA2SGYXTGCFSWJEIIFM2YI2QWN2ES6EJQ5VGROM5W4BZ3`,
loan manager `CCJTYVKKRD5MQI7BLHF4BYAYFXZS5S5J3SZ33ZXTJC4SA55V27NUBGX2`.

## What was already there (Tranche 1) and what this deliverable adds

- Tranche 1 shipped the Privy embedded wallet, the SEP-53 login signed by Privy and `deposit` /
  `withdraw` / `borrow` / `repay` signed through the active-signer registry
  (`frontend/src/lib/stellar-signer-registry.ts`, `privy-signer.ts`, `stellar-contracts.ts`): PRs
  **#4** (Privy adapter), **#7** (auth message signable by Privy), **#8** (key export), **#12**
  (testnet activation + KYC in the app). The Tranche 1 reviewers asked for #4 and #12 to be listed
  next to #7: done here.
- The score path was already implemented for Soroban: `POST /loan/inform-repayment` verifies the
  `loanclos` event over RPC and calls `set_user_risk` (`backend/src/loan/loan-repayment.service.ts`),
  and the `chain-sync` cron reconciles closures every 10 min. What Tranche 1 never recorded is **one
  run with all four steps together** (Privy onboarding → borrow → repay → score written on-chain).
- Tranche 2 changes on the app (branch `scf/t2-hardening`): the Privy wallet is the primary account
  whenever it is the active signer (`WalletProvider.tsx`, before Freighter won if installed); the
  lend UI understands the vault's `decimals_offset` (shares are 1 000× the asset unit on the new
  pairs); regenerated TypeScript clients from the deployed T2-A contracts; `Dockerfile.stellar` and
  the backend defaults point to T2-A; `VITE_FREIGHTER_DISABLED` is a build arg.

## The recorded run (to fill)

Preconditions (ops): backend on T2-A (`SOROBAN_VAULT`, `SOROBAN_LOAN_MANAGER`, `SOROBAN_USDC_SAC`
= Circle testnet USDC), `STELLAR_OPERATOR_SECRET` = the key holding the **underwriter** role of the
T2-A loan manager, `KYC_GATE_ENABLED=true`; frontend built from `Dockerfile.stellar` (T2-A ids);
the vault holds enough idle USDC for the borrow (LP deposit or seed).

| Step | Actor / signer | Expected | Tx / value |
|---|---|---|---|
| 1. Sign in with a fresh email ("Continue with email") | Privy | embedded Stellar wallet created; friendbot + USDC trustline automatic | wallet `G…` |
| 2. `/loan/verify` (phone OTP) | backend underwriter | first `set_user_risk` (score 1, limit 1 USDC) | `riskset` tx |
| 3. Borrow before KYC | app | **403 identity verification required** | — |
| 4. KYC sandbox approval | backend | `kycStatus = approved` | — |
| 5. `POST /loan/borrow` → offer; `borrow_with_term` signed by **Privy** | Privy wallet | `loanopen`, USDC arrives in the Privy wallet | `borrow` tx |
| 6. `repay_partial(preview + cushion)` signed by **Privy** | Privy wallet | `loanclos` + `repay` events; refund of the cushion in the same tx | `repay` tx |
| 7. `POST /loan/inform-repayment` | backend | response `score` 1 → 2, `creditLimit` 1 → 3 USDC | — |
| 8. On-chain score | loan manager | `get_user_risk(wallet)` before: score 1 / limit 1; after: score 2 / limit 3 (`set_user_risk` by the underwriter) | `riskset` tx |
